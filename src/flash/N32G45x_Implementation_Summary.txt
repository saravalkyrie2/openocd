# N32G45x Flash Driver for OpenOCD - Implementation Summary

## Overview
Successfully created a working OpenOCD flash driver for the Nations N32G45x microcontroller. The driver addresses the register address differences that were causing read errors with the generic STM32F2x driver.

## Problem Solved
The STM32F2x flash driver uses incorrect register base address (0x40023c00) for N32G45x. The correct base address is **0x40022000**, which caused all flash operations to fail with read/write errors.

## Solution Delivered

### 1. New Driver File: `src/flash/nor/n32g45x.c`
A complete, working flash driver with the following features:

#### Supported Operations
- **Erase**: Individual sectors or mass erase
- **Write**: 32-bit word-aligned programming
- **Read**: Via OpenOCD's default flash read
- **Probe**: Device identification and memory sizing
- **Verify**: Basic erase verification

#### Key Implementation Details
```
Flash Base: 0x08000000
Page Size: 2048 bytes (2KB)
Typical Size: 256KB (128 sectors)
Register Base: 0x40022000

Unlock Keys:
  KEY1: 0x45670123
  KEY2: 0xCDEF89AB

Flash CR Bits:
  [0] PG      - Programming enable
  [1] PER     - Page erase
  [2] MER     - Mass erase
  [6] START   - Start operation
  [7] LOCK    - Lock flash controller

Flash SR Bits:
  [0] BUSY    - Operation in progress
  [2] PGERR   - Programming error
  [3] PVERR   - Verification error
  [4] WRPERR  - Write protection error
  [6] EVERR   - Erase verification error
```

## How to Use

### 1. OpenOCD Configuration File (n32g45x.cfg)
```tcl
source [find interface/stlink.cfg]
transport select hla_swd
set CHIPNAME n32g45x
set CPUTAPID 0x2ba01477
source [find target/swj-dp.tcl]
swj_newdap $CHIPNAME cpu -irlen 4 -ircapture 0x1 -irmask 0xf
set _TARGETNAME $_CHIPNAME.cpu
target create $_TARGETNAME cortex_m -chain-position $_TARGETNAME
flash bank $_CHIPNAME n32g45x 0x08000000 0x40000 0 0 $_TARGETNAME
```

### 2. Flash Operations in OpenOCD
```tcl
# Connect
openocd -f n32g45x.cfg

# In console:
> halt                           # Stop target
> flash info 0                   # Show flash info
> flash erase_sector 0 0 0      # Erase sector 0
> flash write_bank 0 app.bin 0  # Write firmware
> verify_image app.bin 0x08000000 # Verify
> reset run                      # Run
```

### 3. GDB Usage
```bash
gdb firmware.elf
(gdb) target extended-remote :3333
(gdb) monitor reset init
(gdb) load
(gdb) break main
(gdb) continue
```

## Technical Notes

### Flash Programming Sequence
1. Unlock flash controller with KEY1, KEY2
2. Clear status register
3. Set flash address (for erase) or enable PG bit (for write)
4. Set START bit
5. Poll BUSY bit in SR
6. Check for errors in SR
7. Lock flash controller

### Register Layout (0x40022000 offset)
```
+0x00  FLASH_AC      (Access Control)
+0x04  FLASH_KEY     (Key register)
+0x08  FLASH_OPTKEY  (Option key)
+0x0C  FLASH_SR      (Status)
+0x10  FLASH_CR      (Control)
+0x14  FLASH_ADD     (Address for erase)
+0x1C  FLASH_OBR     (Option bytes)
+0x20  FLASH_WRP     (Write protection)
```

### Page Addressing
- Page 0: 0x08000000 - 0x08000800
- Page 1: 0x08000800 - 0x08001000
- ...
- Page N: 0x08000000 + (N × 2KB)

## Known Limitations

- ⚠️ Write protection not fully implemented (stub returns OK)
- ⚠️ No OTP (One-Time Programmable) memory support
- ⚠️ No security feature implementation
- ⚠️ Single bank mode only (no dual-bank support yet)
- ⚠️ No read-out protection support
